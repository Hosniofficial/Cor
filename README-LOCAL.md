# CAESER OF ARABS — التشغيل المحلي

## المتطلبات

- XAMPP: MySQL وPHP 8.x.
- Node.js 18 أو أحدث، واعتماديات `node_modules`.

## هيكل المشروع

- `caesar-web`: صفحات اللعبة وموجّه الويب.
- `caesar-api`: واجهات PHP والخدمات الخلفية.
- `caesar-ws`: خادم WebSocket وواجهات HTTP الخاصة به.
- `caesar-admin`: ملفات لوحة الإدارة، وتبقى متاحة محلياً تحت `/admin`.
- `caesar-assets/web` و`caesar-assets/api`: أصول الواجهة وبيانات JSON؛ حزمة العميل الرئيسية هي `js-3.4.113/caesar-client.js`. أصول إعادة عرض المعارك محفوظة في `caesar-assets/web/battle-replay`، لكن مسارات إعادة العرض القديمة غير مفعلة في بيئة التطوير.
- `caesar-shared`: وحدات JavaScript المشتركة بين الخادم والاختبارات.
- `database` و`migrations` و`tests`: ملفات التشغيل والاختبارات والترحيلات.

يستخدم طلب دخول اللعبة `authToken` ويعيد الخادم `AuthToken`؛ وتخزنه الحزمة داخلياً في `Caesar.Config.AuthToken`. تستخدم واجهات `getWorldCity` و`getRankEffect` و`getPlayerTeam` و`AArenaChallange/getArenaData` و`AArenaChallange/getFightList` و`ACityWounded/getCityWounded` طلب `POST` وترسل `token` في جسم الطلب لا في عنوانه، ويتحقق الخادم من التوكن ويرفض طلبات GET القديمة. يفتح WebSocket بلا بيانات اعتماد في عنوان الاتصال، ثم يرسل `Auth/Authenticate` مع `idPlayer` و`authToken` كأول رسالة؛ يرفض الخادم أي إجراء قبل نجاح المصادقة.

## التشغيل

قبل أول تشغيل، نفّذ `powershell -ExecutionPolicy Bypass -File setup-local-tls.ps1` من جذر المشروع. ينشئ شهادة تطوير لـ`localhost` في `%LOCALAPPDATA%\CAESER\local-tls` ويضيفها إلى مخزن الشهادات الموثوقة للمستخدم الحالي؛ يبقى المفتاح الخاص خارج المستودع وبصلاحيات مقيدة للمستخدم. بعد ذلك شغّل `start-servers.bat`؛ يقدّم خادم WebSocket وواجهة خريطة العالم TLS مباشرة:

- اللعبة ولوحة الإدارة: <http://localhost:8082/>
- لوحة الإدارة: <http://localhost:8082/admin>
- API: <http://localhost:8092/>
- WebSocket وخريطة العالم: `wss://localhost:8081`

الخادم يرفض بدء التشغيل من المشغّل المحلي إذا لم يجد ملفات TLS. هذا إعداد تطوير محلي فقط؛ لا تستخدم الشهادة المحلية في الإنتاج.
يضغط موجّه PHP المحلي ملفات النصوص الثابتة المدعومة بـgzip عندما يعلن المتصفح ذلك، لتقليل نقل ملفات JavaScript وCSS وJSON الكبيرة. يجب ضبط ضغط الأصول أيضاً في Apache أو Nginx عند النشر؛ لا يمر النشر الإنتاجي عبر الموجّه المحلي.

تُجمع ملفات CSS الخاصة باللعبة في ثلاث حزم مع الحفاظ على ترتيب تحميلها الحالي. بعد تعديل أي ملف مصدر، أعد إنشاء الحزم باستخدام `npm run build:game-css` قبل النشر.

المشغّل المحلي يستخدم `caesar_test` لتجنب توجيه التطوير إلى قاعدة الإنتاج. يستخدم الأمر `start-servers.bat test` البيئة `test` على قاعدة `caesar_test` أيضاً.

## إعدادات الإنتاج

تُقرأ الإعدادات من متغيرات البيئة ذات السابقة `CAESAR_`، ومنها `CAESAR_ENV`, `CAESAR_DB_HOST`, `CAESAR_DB_PORT`, `CAESAR_DB_NAME`, `CAESAR_DB_USER`, `CAESAR_DB_PASSWORD`, `CAESAR_API_URL`, `CAESAR_PUBLIC_WS_HOST`, `CAESAR_PUBLIC_WS_PORT`, `CAESAR_INTERNAL_API_TOKEN`، و`CAESAR_GOOGLE_TRANSLATE_API_KEY` الاختياري لترجمة رسائل الشات. لا تضع الأسرار في ملفات المستودع. بيئة الإنتاج تتطلب اتصال API عبر HTTPS وعناوين WebSocket عامة خلف TLS proxy، ومستخدم MySQL محدود الصلاحيات.

أزيلت التحويلات والروابط إلى الموقع والمنتدى القديمين من النسخة المحلية. التحويلات المؤقتة بعد استبدال الجلسة أو فتح الحساب من جهاز آخر تستخدم `http://localhost:8082/`، وأزيلت روابط المنتدى لأن نسخة منتدى محلية غير متاحة.

**قبل الإنتاج:** استبدل `http://localhost:8082/` بعنوان CAESER الإنتاجي المعتمد، وأضف رابط دعم/منتدى إنتاجي بعد اعتماده. لا تترك عنوان localhost في النسخة المنشورة. يحتاج Apache/Nginx الإنتاجي أيضاً إلى إعداد مسارات/aliases للأصول المنقولة إلى `caesar-assets` ولوحة الإدارة المنقولة إلى `caesar-admin`. موجّه PHP المحلي يقدّمها للتطوير فقط.

ملف `ssl-cert.pfx` المحلي يستخدمه `gen-pem.js` للفحص الاختياري، وليس شهادة إنتاج. إذا كان حقيقياً أو استُخدم خارج التطوير فدوّره، ولا تخزّن كلمة مروره في المستودع.
